## Changes

- `grid.js`: draws one SVG line and arrow per `pathCables(path)` entry, colored by `wireColor(c)`. Parallel stretches are 6px apart, centered around the original route, with joined perpendicular offsets at corners. Crossings use the offset routes. One cable has zero offset; empty paths retain the existing dashed gray line. Each path label contains stacked cable buttons.
- `app.js`: shared cable-row rendering for grid, full/compact tree, and home fan labels. Each editor button calls `openPath(path.to, c.id)`; guests use the existing `openLineMenu` read-only behavior. The tree wrapper preserves the feeder-colored line, notes, conduit label, and tube swatches from `pathEl` without changing `paths.js` or nesting buttons.
- `print.js`: the path/conduit table cable cell joins all cable names and fiber sizes as `Name (nF), Name (nF)`.
- `check.js`: reports multiple ending cables when at least one is not an equipment tail. Ends are arriving spans without `nextSpan`; equipment tails are identified by `eq.tail` matching `cableStart(c).id`. The message uses the count of ending cables and `incomingCable` name. It uses `problem(...)` as explicitly requested by the spec.
- `styles.css`: small stacked-row gaps, inherited typography, keyboard focus outlines, and individual row hover. Selected grid lines retain each cable's color and gain a glow.

`fold.js` was not changed; its feeder-based `--wire` behavior remains intact. No model functions or prohibited files were changed.

## Clarifications and limitations

1. **Warning rule clarified by the user:** the prose requiring more than one non-tail was wrong. The intended rule is 2+ cables ending at a location with at least one non-equipment-tail cable. The user explicitly selected this behavior during the task; the implementation and X acceptance check follow it.
2. The spec calls the new diagnostic a warning but explicitly asks for `problem(...)`. The implementation follows the named helper, so its returned level is `problem`.
3. **Existing full-print overview bug:** an extra `buildSheet()` check with the default overview enabled throws `TypeError: Cannot read properties of undefined (reading 'from')` at `print.js:304`, in `drawPanels`. Reproduced the same exception in a fresh isolated browser serving the original five source files directly from `git show c4b5055:<file>` using request interception, without modifying the checkout. This is not introduced by T2 and was left unchanged. The requested path table and actual summary-only print generation pass.
4. Drawing verification covers the specified two-tail fixture, three mixed-color cables, and several route directions/corners. It does not claim exhaustive visual coverage for arbitrarily large cable bundles or all possible crossing arrangements.
